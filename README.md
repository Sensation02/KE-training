# KE Training

Інтерактивний тренажер для підготовки до KE-асесментів. Зараз реалізовано рівень **L3 Full-stack**; структура закладена так, щоб додавати L2/L4 без переробки коду (див. `DEPLOY_PLAN.md`).

## Як зібрати локально

```bash
make build   # зібрати dist/ з levels/*/ (python3 build_study.py)
make check   # лише перевірити інваріанти матеріалів, без запису dist/ (python3 build_study.py --check)
make open    # зібрати (за потреби) і відкрити dist/index.html у браузері
make clean   # видалити dist/
```

Залежностей, крім `python3` (стандартна бібліотека), не потрібно.

## Як влаштовано

- `levels/<Рівень>/` — джерело матеріалів: розділи `NN_*.md` + один `*_Checklist.md` на рівень (зараз лише `levels/L3/`).
- `levels/<Рівень>/source/` — необов'язкова тека з вихідним документом рівня: оригінальна матриця компетенцій (`.xlsx`) і її дослівний Markdown-рендер, з якого зроблено матеріали. Рендер вбудовується у сторінку рівня і відкривається оверлеєм із вкладки ✅ чеклист — видно, звідки взявся кожен пункт і що в матеріали свідомо не ввійшло. Рівень без цієї теки збирається як раніше.
- Кожен пункт чеклиста посилається на питання, які його покривають, HTML-коментарем `<!-- q:front-end/Q1 -->` (кілька — через кому). В UI це клікабельні чипи з кольором статусу вивчення; биті посилання валять збірку, непокриті пункти/питання збірка показує як попередження.
- Кожна відповідь починається блоком `**🎯 Відповідь на іспиті:** …` — еталон усної відповіді екзаменатору (схема і правила — в [`ANSWER_SCHEMA.md`](ANSWER_SCHEMA.md)). Збірка вимагає цей блок першим абзацом кожного питання.
- Вкладки рівня: 📖 читалка (🎯-еталон виділено на початку відповіді), 🎴 флеш-картки (самоперевірка проти 🎯-еталона, повний розбір — за кнопкою), ✅ чеклист.
- Читалка і флеш-картки мають один і той самий набір фільтрів — три мультивибірні дропдауни «Категорії / Рівні / Статус», зібрані спільним `makeDropdown()`. Статус — це «Не чіпалося / Вчу / Знаю» (ті самі три стани, що й кнопка статусу питання). Усередині панелі кожен рядок перемикається окремо, рядок «Усі» — тумблер усе/нічого (звідси дешеве «лише це»: зняти все і вибрати одне). Статус живе в прогресі й синхронізується, сам вибір фільтрів — ні: він скидається з перезавантаженням сторінки і при переході з чеклиста в читалку.
- Пошук інформації — у тому ж рядку, на протилежному боці від фільтрів; працює як ще один фільтр (лишаються питання, у чиєму заголовку, 🎯-еталоні чи розборі є запит), від 3 символів і з дебаунсом ~220 мс. **Охоплення поки одне — відкритий рівень (L3)**: сторінка рівня самодостатня і містить лише його дані. Для L1–L2, L4–L6 це треба розширити на всі курси (спільний індекс від збірки або запит до бекенда) і показувати рівень у результатах — деталі в коментарі до `matchQ()` у [`study_template.html`](study_template.html).
- Дропдаун навмисно свій, а не нативний `<select>`: нативне меню на macOS відкривається поверх самого контрола, а тут панель має розкриватися строго під ним; плюс нативний селект не вміє мультивибір без Ctrl.
- `build_study.py` — python-генератор: парсить `.md`, валідує інваріанти (номер питання, глибина 🟣/🔵/🟢, блок «🎯 Відповідь на іспиті», формат чеклиста, посилання чеклист→питання) і вбудовує дані як JSON у `study_template.html`.
- Результат — статичний `dist/`: кореневий `dist/index.html` (список рівнів) + `dist/<рівень>/index.html` (самодостатня сторінка рівня). `dist/` генерується збіркою і в git не комітиться (див. `.gitignore`).
- `functions/api/state.js` — Cloudflare Pages Function: `/api/state` (GET/PUT прогресу) поверх Cloudflare KV.
- Прогрес синхронізується між пристроями одного користувача через Cloudflare KV; автентифікація і ідентичність користувача — через Cloudflare Access.
