# InterCode Competency Matrix — L3 (Middle)

> Дослівна копія аркуша «L3 (Middle)» з `L3-competency-matrix.xlsx`. Текст
> перенесено без правок — друкарські помилки джерела збережено навмисне.
> Кожен пункт підписано адресою клітинки в оригіналі (`B15`), щоб його можна
> було звірити, і міткою заливки.
>
> **Мітки заливки:** 🟩 `#D9EAD3` · 🟨 `#FFF2CC` · 🟥 `#F4CCCC` · ⬜ без заливки.
> Заливка в джерелі ділить кожну колонку на два блоки, але робить це
> неузгоджено: у технічних колонках зеленим позначено нижній блок, у решті
> рожевим — верхній. Офіційної легенди в книзі немає, тож мітки тут описують
> лише сам факт заливки, без тлумачення.
>
> Технічні категорії `Front-End`…`Software development methodology` лягли
> в основу [`L3_Checklist.md`](../L3_Checklist.md) і навчальних розділів;
> `Загальні вимоги` і `Навики роботи у команді`…`Менторська програма`
> в матеріали не входять — оцінювання по них іде окремо від технічних знань.


## A · Загальні вимоги

- `A2` ⬜ Досвід роботи: 2+ роки.
- `A3` ⬜ Залученість у проєкти: ведення окремих модулів або компонентів великих проєктів. Самостійна робота над завданнями середньої складності, взаємодія з іншими командами, участь у прийнятті рішень.

## B · Front-End

- `B2` ⬜ Вміє правильно та ефективно використовувати дебаггінг у браузері.
- `B3` ⬜ Вміє створювати npm package, опублікувати його та використати в проекті.
- `B4` ⬜ Має впевненні знання та навички роботи у React та/або
- `B5` ⬜ Має впевненні знання та навички роботи у Angular.
- `B6` ⬜ Вміє правильно використовувати state-manager в UI-frameworks або RxJs (Angular).
- `B7` ⬜ Має глибокі знання в HTML+CSS (є розуміння сумісності у різних браузерів).
- `B8` ⬜ Знайомий з front-end build tools (Webpack, Gulp).
- `B9` ⬜ Має загальні поняття lazy loading (modules) та performance optimization (memory snapshots, effective browser debugging).
- `B10` ⬜ Має базове поняття unit-testing.
- `B11` ⬜ Має базове поняття e2e.
- `B12` ⬜ Має навики перехоплення запитів (interceptors, transient requests, global error handling).
- `B13` ⬜ Вміє вибрати необхідну бібліотеку (npm), відповідно до бізнес-вимог, а також враховуючи її розмір, секюріті та модульність.
- `B15` 🟩 Вміє налаштувати з нуля UI-бібліотеки на проєкті (Mantine, Ant, shadcn, etc)
- `B16` 🟩 Вміє вибирати бібліотеки (npm package) для UI-них завдань (e.g.: date-time management, ). Розуміти, як це впливає на розмір bundle, на performance, вміє використовувати bundle analyzer. Опціонально: bundlephobia
- `B17` 🟩 Має розуміння та вміє використовувати state-manager в UI-frameworks (Redux, react-query, React Context, Zustand)
- `B18` 🟩 Має розуміння роботи local storage, session storage, cookies та їхнє можливе використання. Знає їхні обмеження, переваги з точки зору security
- `B19` 🟩 Вміє правильно та ефективно використовувати дебаггінг у браузері (profiling, може ідентифікувати performance issues and bottlnecks за допомогою інструментів браузера)
- `B20` 🟩 Знає та вміє використовувати специфічні інструменти під фреймворки або бібліотеки (напр, debugging plugin for React or Angular)
- `B21` 🟩 Розуміє принцип версіонування packages та застосунків, зокрема semver. Розуміє принципи створення npm package та його публікації. Специфіка створення private package та подальшої роботи з ним (як задати npm_token, що таке .npmrc файл)
- `B22` 🟩 Вміє проєктувати структуру компонентів та їхнє функціональне призначення на рівні кодової архітектури застосунку (page components, feature components, components librabry etc)
- `B23` 🟩 Вміє створювати reusable/shared pieces of UI code (components, hooks, utils). Вміє ідентифікувати необхідність їхнього створення.
- `B24` 🟩 Розуміє види state-ів (component state, global state, server state, browser state). Розуміти методи пропагації даних (top-to-bottom – ReactContext, event injection – Redux)
- `B25` 🟩 Вміє інкапсулювати та структурувати state, напр. feature-based.
- `B26` 🟩 Розуміння clear/generic components, вміти обрати рівень state-у для збереження різних видів даних
- `B27` 🟩 Має розуміння, як оптимізувати великий UI-застосунок (використання lazy-loading, оптимізація bundle (chunks), правильна модуляризація)
- `B28` 🟩 Має базове поняття unit-testing (визначення, що потребує тестування, мати поняття про mocks, fakes; shallow, mount). Має розуміння про pre-conditions та post-conditions.
- `B29` 🟩 Знання принципів написання коду, який має high-testability (чисті та імутабельні функції, які є важливими для бізнес-логіки)
- `B30` 🟩 Має базове поняття e2e (що воно включає, чим відрізняється від unit-testing, хто його проводить, чому воно потрібне)

- `C29` 🟩 Вміти реалізувати Global error handling (на прикладі NestJS або іншого фреймворку). Способи логування, та їх подальшого збору в систему моніторингу (stdout, file, json, etc).

- `C31` 🟩 Розуміє та вміє застосовувати WebSockets та SSE (server-side events). Розуміти, які є особливості роботи WebSockets та SSE при використанні більше аніж однієї репліки застосунку.

## D · Databases

- `D3` ⬜ Знає як працюють реляційні бази даних (на більш низькорівневому рівні).
- `D4` ⬜ Знає як працюють не-реляційні бази даних.
- `D5` ⬜ Вміє нормалізувати структури даних (1n 2n 3n).
- `D6` ⬜ Має базовий досвід з бек-ап-ом та розгортанням БД.
- `D7` 🟩 Має розуміння транзакційності relational DB, коли і для чого використовувати.
- `D8` ⬜ Являється продвинутим користувачем IDE (DataGrip), вміє проводити аналіз запиту (EXPLAIN, etc), performance analysis (full scan, indexed scan)
- `D9` 🟩 Мати знання, коли потрібно використоувати ORM, а коли raw SQL
- `D10` 🟩 Вміє писати більш складні SQL запити, GROUP BY, nested SELECT, WITH statement, PARTITION BY (for grouping), ROW NUMBER
- `D11` 🟩 Мати базові знання про DB triggers (e.g. for audit log at DB level)
- `D12` 🟩 Знає, як працюють не-реляційні бази даних: коли їх необхідно вибирати, як структурувати дані, коли варто деструктурувати дані (та які є фізичні обмеження зі сторони БД), як робити запити для отримання цих даних, flattening даних, навігація в даних, як можна (в теорії) масштабувати не-реляційні БД.
- `D13` 🟩 Має розуміння, які види бекапів є (incremental, full-backup), коли є сенс в кожному з них (залежно від розміру БД та сервісу розгортання БД)
- `D14` 🟩 Має розуміння транзакційності relational DB (вміти використовувати транзакції в одній з ORM), мати розуміння, як інший код може впливати на транзакції й чи він потребн всередині транзакції або ні.
- `D15` 🟩 Знати, що таке profiling SQL запитів, проводити аналіз slow query log
- `D16` 🟨 (опціонально) Вміти робити shared queries для команди (використовувати відповідні платформи)
